## 第三批：已完成

**目标：宿主决定使用哪些图形、命令和服务；内核通过最少的公开接口使用它们，不再自行选择和创建默认依赖。**

下面四步已按顺序完成并独立提交。实现记录见 [第三批记录](20261119_REFACT_PUBLIC_CONTRACTS.md)。

### 第一步：整理公开接口（已完成）

- Document 查询统一返回 ShapeNode，通过 node.value 取得 Shape；保留 findNode/requireNode，移除 requireShape、find、shapes 等重复模型快捷入口。
- 节点父子读取直接使用 node.parent()/children()；Document.children() 只读顶层节点，保留必要的 indexOf 和结构操作。去掉重复的关系转发、目标定位包装；只有批量用例实际需要的预检查继续公开。
- ShapeFactory 使用侧保持 has/definition/create。ShapeClass 留在工厂文件内部，不导出；宿主直接注册具体类，不引入 Provider 或新的定义包装类型。
- 按上述边界建立一个公共导入入口，只开放领域模型、属性规格、只读节点、必要文档能力、工厂、命令和持久化契约；不开放关系存储或节点写入权限。

结果：调用方只有一套节点查询方式；插件和宿主有明确的公共导入入口，不能绕过 Document 修改树。保持现有 CLI 错误内容和检查顺序，实施时同步 AGENTS.md 中旧的公开方法说明。

### 第二步：把具体能力选择移到宿主（已完成）

- ShapeFactory 不再导入或自动注册六种内置图形，空工厂只负责注册、规格查询和创建。
- 在宿主组合根统一选择并注册默认图形，装配现有内置命令和文件、SVG 服务；不把插件发现或配置加载提前放进这一批。
- 明确课程 ShapeProvider 对应具体图形类的静态定义和构造契约，不另写一套包装对象。

结果：新增图形不再修改工厂；默认 CLI 仍由宿主组装出与原来一致的能力。

### 第三步：让内核接收依赖（已完成）

- Workspace 接收宿主提供的 ShapeFactory、文件访问及 SVG 读写服务，继续管理当前文档和路径。
- Client 接收装配后的 Workspace，负责命令分发和历史执行，不自行建立默认文档服务。Invoker 保持独立，不重新依赖 Workspace。
- save 复用会话中注册过映射的 writer。创建通过 Factory 得到 Shape，再交给 Document.insert 得到节点；工厂不管理文档关系。

结果：测试可以替换文件服务、工厂或 writer；内核不需要知道宿主具体选用了哪些实现。

### 第四步：统一验收（已完成）

- 验证空工厂、默认宿主、依赖替换和公共入口可供独立测试扩展使用。
- 验证查询返回节点、模型引用和节点身份不变，CLI 的参数、错误、回显、help 顺序和 read/save 计数兼容。
- 运行全量测试和类型检查；检查内核不导入宿主或具体插件，扩展不导入节点关系存储。
- 更新架构说明和本计划，停在第三批验收点，再决定是否进入第四批。

结果：独立测试扩展只导入公共入口即可定义 Shape 和 EditCommand，注册、help、执行及多轮 undo/redo 均通过，节点及模型身份不变。默认 CLI 回放和读写回归全部通过。源码检查确认 backend 不导入 host，Factory、Document、Workspace、Client 和内置命令不导入具体图形；默认服务构造只在宿主。

## 第四批：已完成

目标是独立注册领域属性语义，保留普通属性默认规则。本版替代此前“多命中拒绝”的安排，最终契约为按启用顺序首次命中。

1. **契约和装配**：公开 AttributeHandler 静态契约与 AttributeHandlerRegistry 注册表；只提供 register/resolve，Workspace 必传依赖，宿主注入独立空表。注册名、静态方法及重复注册检查完成。
2. **命令接入**：matches 集中处理实际模型、key 和别名；SetCommand 定位 Shape 后查询首个命中项，调用 apply/display，零命中回退模型。模型快照覆盖修改及回显失败，成功才更新撤销记录；Invoker 不变。
3. **统一验收**：独立静态测试扩展只导入公共入口；验证顺序优先、别名、默认回退、多部件撤销、失败历史不变、重试及 CLI 错误后继续执行。架构说明和 ADR 已更新，全量测试及类型检查通过。

不维护额外属性映射，不实例化 Handler，不实现正式 Box 或通用事务。具体接口、错误及恢复边界见 [第四批记录](20261120_REFACT_ATTRIBUTE_HANDLERS.md)和[契约 ADR](../adr/20261120_ATTRIBUTE_HANDLER_CONTRACT.md)。

## 第五批：已完成

1. **模型数据契约**：Shape.parse 通过属性规格解析文本并构造模型；返回模型及仍应成为节点的子 Shape。ShapeFactory 提供 parse，不公开具体注册类。模型不依赖 XML 或节点关系。
2. **Reader 编排**：按 data-kind 或原标签选择类型，提供缓存的递归子 Shape；模型消费私有部件，其余成员保留节点关系。类型缺失按标签降级，已安装但结构无效拒绝。全输入 id 在构造前校验，成功后才替换文档。
3. **Writer 与验收**：映射生成私有部件，Writer 追加文档成员；完整映射结果先校验再写出。公共测试模型覆盖往返、嵌套、失败恢复及内部部件不产生树行，默认 CLI 全量回归通过。

接口、限制与错误策略见 [第五批记录](20261120_REFACT_SVG_PARSE.md)和[读回 ADR](../adr/20261120_SVG_COMPOSITE_PARSE.md)。后续 identifiers() 已补齐创建时私有部件 id 检查，Document 保持节点索引与模型组成分离。

## 第六、七批：按当前范围已完成，等待验收

- **树装饰**：TreeCommand 委托 TreeRenderer，经典 Decorator 按列表顺序追加标签，状态属于实例；空链兼容原输出，不展示私有部件。Client 在历史提交成功后发布只读 edit/undo/redo/replace/save，失败不通知，观察者异常仅产生警告。
- **全部发现**：main 扫描应用 plugins/ 的直接子包，按目录名排序并全部加载，目录缺失仅保留五个框架入口。新增包不修改内核或发现逻辑，不引入配置选择。
- **原子装配**：公共 ExtensionContext 暂存四类贡献及附属 SVG 映射，激活后比较 contributes 并构建独立候选装配；重复、声明错误或激活失败丢弃当前包全部注册并继续。代码和发现共用同一路径。
- **创建约束**：模型通过 identifiers 声明自身及私有部件占用，Document 在创建及结构恢复前统一校验，失败不修改关系。

记录与设计见[剩余架构实现](20261120_REFACT_EXTENSION_ASSEMBLY.md)及[ADR](../adr/20261120_TREE_AND_DISCOVERY.md)。配置注册、白名单、禁用和 options 明确暂缓，因此不宣称完成 Phase 2 的配置装配交付。

## 始终保持的边界

- Shape 维护领域状态和私有部件，不维护文档父子关系、归属或通用 children。
- Document 通过 ShapeNode 组织树，Command 编排用例，历史保持现有 Command 模式。
- 不为形式对称新增服务框架、执行结果或历史项类型，不恢复通用事务。
- 每批完成后验收，不连续推进未验收批次；本批按用户要求每步独立提交，不自动打标签或发布。
