# VS Code SVG 文件标记

- 记录于 2026-11-25，所属阶段为 Phase 2，任务书 A.1
- 已实现并验收，证据见 [VS Code 验收](../../../vscode-extension/docs/acceptance.md)；可与 [原生 SVG 大纲](20261125_VSCODE_OUTLINE.md) 独立推进

## 需求背景

用户在 VS Code 工作区中浏览文件时，需要快速识别可编辑的 SVG。课程要求在原生 Explorer 的条目右侧显示 `[]`，文件名和内容继续由工作区文件提供。

## 决策记录

| 议题 | 选项 | 决定 | 理由 |
| --- | --- | --- | --- |
| 标记位置 | 自定义列表 / Explorer 条目附加标记 | 使用原生 Explorer | 用户沿用已有的工作区导航。 |
| 匹配依据 | 查看文件内容 / 按文件类型与扩展名 | 识别扩展名为 `.svg` 的文件 | 与任务书范围一致，目录通过资源类型排除。 |
| 文件状态 | 改写文件 / 由宿主展示附加信息 | 由宿主展示，扩展只提供标记 | 原文件可继续被现有工具读取。 |

## 职责边界

VS Code 提供工作区资源和 Explorer 展示。扩展判断哪些条目需要 SVG 标记并返回展示数据。大纲、XML 结构读取和源码定位由 [A.2](20261125_VSCODE_OUTLINE.md) 负责。真实运行证据由 [A.3](20261125_VSCODE_EVIDENCE.md) 汇总。

## Cases 处理策略

| 场景 | 输入或前置状态 | 预期行为 |
| --- | --- | --- |
| SVG 文件 | 工作区包含 `example.svg` | Explorer 的文件条目旁显示 `[]`，原文件名与内容保持原值。 |
| 普通文件 | 工作区包含 `notes.txt` | 文件条目保持普通样式。 |
| 目录 | 目录名为 `assets` 或 `assets.svg` | 目录条目保持普通样式。 |
| 同目录混合资源 | 示例文件、普通文件和目录同时出现 | 以单个资源的类型和文件名分别判定标记。 |

## 接口契约

输入为 Explorer 条目对应的资源标识和文件类型。符合条件时返回文本标记 `[]`，其他资源返回空结果。文件分类与展示数据足够完成任务。
