# 撤销与重做

- 时间：2026-10-16
- 所属阶段：phase1

## 需求背景

编辑命令须支持撤销与重做（以 Command 模式实现）。文件读写、改画布尺寸这类文档类命令执行后，内存与磁盘的对应关系已经改变，不允许跨越它们撤销。参考：refs/phase_1.md §3（撤销重做）、§4.3、§6。

## 决策记录

| 议题 | 选项 | 决定 | 理由 |
| --- | --- | --- | --- |
| 文档类命令之前的历史，解禁后能否继续撤销 | A：文档类命令成功后清空 undo / redo 栈，解禁后只能撤销之后的编辑；B：保留历史，解禁后可撤销到文档类命令之前 | A | 文档已与磁盘同步或已被替换，跨越它撤销语义不清 |

## 职责边界

- 负责：`undo`、`redo`、undo 单元粒度、redo 栈清空、文档类命令后的禁止与解禁。
- 不负责：各编辑命令被 undo 时的具体回显（归属各命令需求）；哪些命令是文档类（由各命令需求声明：init、canvas 改尺寸、read、save）。

## Cases 处理策略

| 场景 | 输入 / 前置状态 | 预期行为 / 输出 |
| --- | --- | --- |
| 正常 | `move c1 30 0` → `undo` → `redo` | `circle#c1 moved to (130,100)` → `circle#c1 moved back to (100,100)` → `circle#c1 moved to (130,100)` |
| 正常 | `group g1 r1 c1 t1` → `undo` | 一次还原全部成员的原父容器与原位置 |
| 正常 | undo 后 | 文档状态（属性值、父容器、兄弟间顺序）与该命令执行前完全一致 |
| 边界 | `undo` → 新的编辑命令 → `redo` | redo 栈已清空，报"无可重做" |
| 边界 | 编辑命令执行失败 | 不入栈，不清空 redo 栈，不改变禁止状态 |
| 边界 | tree / show / help / canvas（无参） | 不影响任何 undo / redo 行为 |
| 异常 | `save demo.svg` → `undo` | `error: undo not allowed after io command` |
| 异常 | `save demo.svg` → `redo` | 报错：io 命令后不允许 redo |
| 异常 | 文档类命令后执行一次成功的编辑命令，再 `undo` | 正常撤销该编辑（已解禁） |
| 异常 | 栈为空时 `undo` / `redo` | 报错：无可撤销 / 无可重做 |

## 接口契约

| 命令 | 语法 | 说明 |
| --- | --- | --- |
| undo | `undo` | 撤销最近一个编辑命令 |
| redo | `redo` | 重做最近撤销的命令；undo 后若有新编辑，redo 栈清空 |

- 一条编辑命令 = 一个 undo 单元
- redo 的回显与原命令执行时相同
- 编辑类命令：create、delete、move、scale、set、group、ungroup、addto、front、back
- 文档类命令：init、read、save、canvas（修改尺寸）；执行后 undo / redo 禁止，直到下一次编辑命令成功执行
- 显示类命令：tree、show、help、canvas（无参）；跳过
