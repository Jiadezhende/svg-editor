# VS Code 原生 SVG 大纲

- 记录于 2026-11-25，所属阶段为 Phase 2，任务书 A.2
- 已实现并验收，证据见 [VS Code 验收](../../../vscode-extension/docs/acceptance.md)；可与 [文件标记](20261125_VSCODE_FILE_BADGE.md) 独立推进

## 需求背景

用户打开 SVG 源码后，需要了解根元素、容器与叶子的层级，并能从原生 Outline 跳到相应元素。编辑过程中源码会暂时处于未完成状态，大纲应保持可恢复。

## 决策记录

| 议题 | 选项 | 决定 | 理由 |
| --- | --- | --- | --- |
| 展示位置 | 自定义侧栏 / 原生 Outline | 原生 Outline | 使用熟悉的层级和定位交互。 |
| 数据来源 | 读取磁盘文件 / 读取当前编辑文本 | 读取当前编辑文本 | 未保存的修改也应反映到大纲。 |
| 结构和定位 | 仅返回平面标签 / 返回层级及源码范围 | 元素按嵌套关系返回并携带源码范围 | 同名元素和无 id 元素仍可准确定位。 |
| 编辑中的非法 XML | 暂留旧结果 / 返回空结果 | 允许清空并在下次合法输入时恢复 | 不完整输入符合任务书允许的暂态，旧位置不再用来跳转。 |

上述数据与错误处理是当前设计约定。确定实现之前先观察并记录 VS Code 现有 Outline 行为。

## 职责边界

扩展为当前 SVG 文档生成层级、显示名称和源码范围，原生 Outline 承担界面和定位交互。解析以元素结构和位置为目标。图形预览和完整 SVG 规范校验超出本需求范围。

## Cases 处理策略

| 场景 | 输入或前置状态 | 预期行为 |
| --- | --- | --- |
| 有效且嵌套 | `svg` 包含多层 `g`、`rect id="start"` 和无 id 的 `text` | 展示根、容器和叶子。节点可显示 `rect#start`、`text` 等名称。 |
| 源码定位 | 点击原生大纲中的某个元素 | 编辑器跳到该元素的源码范围。 |
| 未保存编辑 | 改 id、插入或移动元素 | 大纲使用当前编辑文本，名字、层级和位置同步更新。 |
| 不完整 XML | 输入时暂时缺少结束标签 | 扩展继续运行，可以暂时清空大纲。补齐后恢复当前结构。 |

## 接口契约

输入为当前 SVG 文本。输出为一棵元素符号树，节点包含显示名称、源码范围、定位目标和子节点。带 id 的元素显示 `标签名#id`，其余元素显示标签名。编辑而未保存时也使用当前文档版本。
